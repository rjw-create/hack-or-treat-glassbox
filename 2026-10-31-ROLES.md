# Roles: Glassbox (open-source entry)

Several Claude sessions work on this repo at once, one per role, each in its own git worktree and branch.
Each role edits only the paths it owns, so pull requests rarely conflict.

| Role | Folder (worktree) | Branch | Owns |
| --- | --- | --- | --- |
| Core | `open-source-project` | `feature/glassbox-mvp` | `glassbox/`, `tests/` except UI tests, `scripts/`, `pyproject.toml`, `docs/2026-10-31-interface.md` (the dated name the file-naming hook requires) |
| Surface + Story | `open-source-project-surface` | `feature/glassbox-surface` | `ui/` (explorer UI), `tours/`, `labels/`, UI tests, `README.md`, `LICENSE`, `docs/demo-script.md`, `submission.md`, backup video |
| Proof | `open-source-project-proof` | `feature/glassbox-proof` | `evals/`, `results/`, eval tests |

## What each role does
- **Core:** the hard technical piece. Writes `docs/interface.md` first: the Python API and the files it produces (for example feature lists and activation records). Records the stack and verify command in `CLAUDE.md`.
- **Surface:** the interface people use to explore results. Builds against fake data that matches `docs/interface.md` until Core's real output exists.
- **Story:** README a stranger can follow from a fresh clone, `LICENSE` (MIT or Apache 2.0), demo script, submission text, backup video. Open source is judged on reuse, so setup instructions matter as much as the code.
- **Proof:** evaluations that show the tool works and where it doesn't. Commit raw results with the script that made them, so anyone can reproduce them.

## Rules
1. Edit only the paths your role owns. If you need a change elsewhere, ask the user to pass it to the owning role.
2. Only Core changes `docs/interface.md`. Any change to it must be called out in the PR description.
3. Before opening a PR, run the project's verify command (recorded in `CLAUDE.md`) and paste the result into the PR.
4. Small PRs into `main`, every hour or two: `gh pr create --base main`. The user approves merges.
5. After a merge, the other roles update with `git fetch origin` then `git merge origin/main`.
6. GPU: shared with another project on this machine. Ask before long training or model runs.
7. Only open-weight models in the core path. Never commit `.env`, keys or tokens.
